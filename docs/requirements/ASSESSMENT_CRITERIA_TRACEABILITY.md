
# DataLens — Assessment Criteria Traceability

## Assessment
Module: B9IS130 — Web Development for Information Systems
Project: DataLens
Assessment: Continuous Assessment 1

## Assessment Components

| Component | Marks |
|---|---:|
| Web Application Development | 70 |
| Technical Report | 20 |
| Presentation and Demonstration | 10 |
| Total | 100 |

## Seven Main Application Criteria

### 1. Requirements Analysis and Planning
Planned evidence:
- Problem statement and project objectives
- Stakeholder and persona analysis
- Functional and non-functional requirements
- User stories and acceptance criteria
- Use-case diagram
- Feasibility and scope analysis
- Research supporting technology decisions

### 2. Front-End Development and UX Design
Planned evidence:
- React-based responsive interface
- Professional dashboard and navigation
- Consistent design system
- Accessible forms and interactions
- Responsive testing
- Clear loading, success and error feedback

### 3. Back-End Development and Database Integration
Planned evidence:
- Node.js and Express backend
- MongoDB database integration
- Modular routes, controllers and services
- Dataset CRUD operations
- Server-side validation
- Centralised error handling
- Dataset version management

### 4. API and Web Service Integration
Planned evidence:
- Documented internal REST API
- External open-data API integration
- JSON data exchange
- Asynchronous request handling
- Loading and error states
- Timeout and external-service failure handling

### 5. Security Implementation
Planned evidence:
- Password hashing
- Authentication and authorisation
- Server-side resource ownership checks
- Secure session management
- Input validation and sanitisation
- File upload security
- Rate limiting and security headers
- Security testing and threat mapping

### 6. Software Engineering Practice and Code Quality
Planned evidence:
- Modular project structure
- Separation of concerns
- Reusable components and services
- Consistent formatting and linting
- Automated tests
- Meaningful Git commits
- Professional README and setup instructions
- Architecture documentation

### 7. Cloud Deployment
Planned evidence:
- Publicly accessible frontend
- Deployed backend API
- Hosted database
- Environment variable configuration
- Persistent file storage
- Deployment verification
- Health checks and CI workflow
- Live application testing

## Project Scope Boundaries

The current application will use deterministic,
rule-based data profiling and remediation.

AI-based analysis and correction are reserved for
possible future dissertation integration.

No AI-powered functionality will be represented as
implemented in this assessment.

## Evidence Management

Testing results, screenshots, architecture diagrams,
deployment evidence, references and development decisions
will be collected throughout implementation.

All reported results will come from actual work performed.
